## Two no-PC, $0 baseline options

### A — Dedicated public GitHub Pages *preview* repository (least new technology)

Create a second repository such as `ejronin/1ADAAR-preview`, publish a copied sanitized `docs/` artifact through Pages Actions under that repository and open `https://ejronin.github.io/1ADAAR-preview/staging-review.html` **only after that repo is created, deployed and HTTP/browser-verified**. It does NOT exist as a verified active URL yet. The production `1ADAAR` Pages site remains entirely independent.

Required owner steps: authorize separate public repo, select its Pages Actions source and authorize a scoped deploy credential (or perform a manual sanitized artifact upload). Never grant a full-account token or copy WARCON/Discord secrets. Relative links are used in current docs; no domain-specific bundle assumptions. Cost typically $0 on public GitHub Free when eligible. Build a test of JS/CSS/JSON paths at the actual deployed origin. GitHub Docs: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

### B — Cloudflare Pages branch preview (useful if Tier 2 Steam consent planned)

Authorize an eligible Cloudflare account, connect `ejronin/1ADAAR` repository with narrow GitHub permissions, set the application output directory to `docs`, identify `feature/v1.1-ia-implementation` as the explicitly controlled preview branch and prevent accidental deployment from `main` to a second public "production" URL. Obtain a real `*.pages.dev` preview hostname after provider deploy, then verify dynamic JSON, relative route links, image requests and mobile screenshots. Worker/D1 consent backend, if later approved, remains separately provisioned with its own binding/privacy review. Cost: free-tier eligibility; verify actual account usage/quota before deploying. Cloudflare documentation: https://developers.cloudflare.com/pages/ and https://developers.cloudflare.com/pages/platform/limits/

## Temporary static source proxy

`raw.githack.com` can sometimes show HTML from a public GitHub commit with correct MIME types, but it is a **third-party unaudited preview proxy** with no uptime guarantee. Its live HTTP load was not verifiable in this engineering environment. **Do not count an unverified proxy URL as the required hosted staging preview** or use it for approving sensitive integrations.

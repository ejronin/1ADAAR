## Check the performance charts

The implemented chart modes are:
1. **Kills & deaths:** two counts per saved completed match, kills green and deaths yellow.
2. **K/D per match:** ratio of kills/deaths for that one saved completed match.
3. **Rolling K/D · 5 matches:** each plot point = (sum kills)/(sum deaths) for the latest five consecutive saved completed matches *up to that point*. It uses overlapping groups.
4. **Career K/D history:** cumulative all-time WARCON K/D saved as daily snapshots, not all matches from the player's lifetime.

The displayed records in any view are sorted **oldest to newest**; the dropdown currently selects the latest 10, 25, or all available plotted observations. With ten rolling points, each point still represents a five-match sample; the first point may depend on four earlier matches outside the window.

The lead has staged clearer tabs, `POINTS SHOWN` selector, dedicated chart explanatory text, chronology labels, and links to the server-wide activity page. Check whether the controls are actually clear to a player. In particular:
- Should rolling K/D remain an overlapping line, or be a 5-match grouped summary? If proposing a change, show the same data side by side in working prototypes and explain trade-offs.
- Is "Career K/D" redundant with "K/D per match"? Explain the differences in a quick first-time-player comprehension test.
- Are the four modes actually useful or just excessive tabs? Which one should default? Could comparisons or dual-axis plots be misleading?
- Does `Last 10` mean ten completed matches or ten observed snapshots? Does source scope change visibly between career and match views?
- Are zeros and zero-death games handled honestly and consistently with WARCON's actual rules? Do not invent a metric convention.
- Evaluate visual hierarchy, axis labels, contrast, keyboard point inspection, exact-value table, hover and mobile 320/375/390 px.

**Provide a screenshot-annotated findings register with actionable fixes**, not vague praise.

## Check the activity heatmap

It lives at `docs/activity.html`, with direct links added to home, player search, sample player and player dossier. **It is a server-wide heatmap of completed-match start times captured by 1ADAAR**, not a personal player activity heatmap. Initially it has *no actual completed matches saved*; empty state is required until evidence exists.

Review whether placing a shortcut under the player chart is confusing, whether a compact server-wide heatmap preview on the home page would improve discovery, and whether a mobile calendar/weekday heatmap at 320 px is practical. Do not populate it with invented bright cells. A separate, explicitly labeled fictional visualization may be created for design explanation but must never resemble live stats. Do not publish player-specific hours/days until a verified session source and privacy policy exist.

## Review the three animations

Owner-approved direction: premium tactical intelligence interface with a **recognizable wow moment** that is worth its rendering cost.

Deliver **three actual browser-operable visual treatments** for comparison, not descriptions:
- A. **Hero laser trim:** luminous narrow border trace following the hero's rounded path once, then stopping. Use the official background art untouched.
- B. **1AD logo circular sheen:** a measured sweep/glint *around/across the real 1AD mark*, deliberately timed after the hero trace. Do not recreate or recolor the official emblem.
- C. **Weekly first-place champion crown:** gold crown graphic fading in just above the *verified* first-place player's portrait, with a restrained gleam. The currently unawarded weekly podium must **not** display the crown or a fake person. Show the effect using a clearly marked isolated fictitious design state outside the production-bound weekly page if necessary.

For each: real responsive rendered screenshots or screen recordings, duration/sequence timings, once-only trigger rules, contrast/readability considerations, CSS/SVG architecture, prefers-reduced-motion static fallback, impact on low-end phones, and comparison of polish versus distraction. No infinite animation loops, excessive glow or effects that obscure data.

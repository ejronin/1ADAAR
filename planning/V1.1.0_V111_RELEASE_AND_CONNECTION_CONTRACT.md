## Progression: six authenticated UX states

| State | Display | Action | Data |
| --- | --- | --- | --- |
| `unlinked` | **Connect WARDOGS progression** | Open Tracker Steam sign-in/sync in a new tab; original dossier remains open | Dashes and neutral unfilled radar |
| `awaiting_verification` | **Tracker synchronized? Verify with Steam in 1ADAAR** | Separate server-side Steam OpenID proof & informed consent | Still blank — a Tracker sign-in alone is not 1ADAAR account ownership |
| `verifying` | **Verifying your Steam connection…** | Disable repeated submit until verified or failed | Blank, accessible live status |
| `connected` | **Connected ✓** · synchronized timestamp | **Refresh progression**, **Manage visibility**, **Disconnect** | Six role XP+levels and overall level/career XP only from authorized fresh public endpoint; cash/gold requires separate opt-in |
| `refreshing` | **Refreshing verified public progression…** | On accepted refresh, update radar, exact-value accessible table and last-sync time | Preserve last known *authorized* values with stale label; never invent numeric deltas |
| `expired_or_revoked` / `error` | **Reconnect** or **Temporarily unavailable** | Reverify ownership or retry on rate limit | Private fields blank, connection state not guessed |

The existing static GitHub Pages implementation intentionally only supports the **unlinked** state and Tracker outbound sync link. It does **not** pretend that returning from Tracker is enough to claim connected. The `Check connection status` control cannot check a secure account without the approved backend.

### Redirect / return and refresh semantics

1. User opens Tracker in a separate tab, preserving `players.html#player-<opaque-hash>` in 1ADAAR. No raw SteamID is placed into a query/fragment or browser storage.
2. User completes Tracker's own Steam login and public synchronization. There is **no guaranteed Tracker redirect/callback** to this product.
3. User returns to the original 1ADAAR tab and selects a separate `Verify connection` flow if ownership/consent service has been provisioned.
4. Server validates a Steam OpenID assertion against Steam, binds identity to the existing private player key through a verified mapping, records consent in a private serverless database, and sets Secure/HttpOnly/SameSite cookies. Session expiry/revocation are enforced by the service.
5. The page requests `GET /api/progression/me` using that authenticated session, with a scoped API returning `state`, allowed exact public fields, synced timestamp and **no raw SteamID**. User consent is independently checked server-side on every request.
6. After verified connection, first fetch starts **automatically**, displays a progress status, then updates the six-axis radar and cards. The former connect prompt becomes **Connected** + Refresh / Visibility / Disconnect. A failure shows a retryable message, not fake numbers.
7. On return to the tab, `visibilitychange` may check verified session status once (with server-side throttle/cache), but must not loop or repeatedly hit Tracker's API. Manual refresh stays available.
8. On disconnect/revoke, server removes consent and clears the browser session; public profile progression/economy disappears and stays hidden across devices. Delete policy and optional cached records are owner-approved before provisioning.

**Provider approval still required:** Cloudflare Workers/D1 or other narrowly scoped authentication/data service, GitHub Pages ↔ session-origin cross-site cookie/CORS details, Steam OpenID domain/return URL, credentials, retention window, revocation, owner consent and real Tracker source validation. Do not ship a fake connection from a localStorage boolean or knowing a SteamID.

## Discord AAR artwork policy

The real Discord post contains a **Python-rendered PNG media attachment** plus native Discord Components V2 container, text, and a legitimate `Open in 1ADAAR` external URL button. The image mockup is the **PNG itself**, not a screenshot of the Discord message surface.

Actual `src/recap_card.py` highlight cards have a full-height line-drawn crosshair / balance scale / ruler glyph; each has (1) award label, (2) source-verified display name, (3) 31px source-supplied measurement. Card widths, borders and numeric baselines are identical. The icon graphics are Pillow-drawn primitives; **no emoji glyphs**.

Only a source-verified known player faction warrants a faction-color outline. Unsupported awards retain a neutral stroke, not an invented team affiliation. Scores/awards remain omitted if missing and no recap may ship without explicit `verifiedCompleted`.

The final Discord client rendering, mobile scaling and button behavior require actual approved private test-channel captures before v1.1.0 release.

# Discord administrator handoff — Dan's WARDOGS server

**Policy:** No changes have been made to Dan's Discord server by this implementation. These are proposed configuration decisions for an administrator; Dan's rules and permissions remain authoritative.

## What works with the existing webhook in v1.1

1. **Match recap channel** — owner/admin confirms the current channel receiving WARCON completed-match recap; do not create a duplicate announcement channel without approval. Existing Github Actions secret `DISCORD_MATCH_WEBHOOK` should point to that destination.
2. **Weekly Sunday report** — confirm the *same or separate* channel to receive Sunday 12:00 PM America/New_York reports, depending on Dan's preferences. Respect the existing server moderation, retention and slowmode rules. No player participation ping by default.
3. **Webhook permissions** — channel/guild policies must permit Manage Webhooks where the admin creates the hook and allow the hook to post media. The webhook token must stay in GitHub Actions secrets, not PR text. Use no role mention permission; `allowed_mentions.parse=[]`.
4. **Recap payload** — native Components V2 type 17, 10, 12 and a real type 2 style 5 URL link under type 1 Action Row. No bot installation is needed to post this message or to operate the link button. Server owner selects the channel.
5. **Private delivery test channel** — request approval for one private `1adaar-testing` channel visible to the server admins (or an existing admin testing channel). Only post manually authorized clearly marked **TEST / FICTIONAL** delivery samples there. Do NOT test in public match recap without permission.
6. **Identity/weekly awards** — a Discord nickname, avatar URL or publicly visible SteamID is not verified membership or consent. Determine who may qualify, how Steam↔Discord proof is privately checked, how players revoke, who can review evidence and what to do after leaving the server. Do not assign podium awards yet.
7. **Future app installation** — do not request Manage Server, Administrator, privileged gateway intents or role-manage capability just to send webhooks. To enable slash commands/interactions in v1.5, first obtain Dan's approval for a narrowly scoped bot/Application installation. Confirm applicable Install Apps or Manage Server permissions and Discord's guild app policy. Use a signed HTTPS interactions endpoint and app public key; host on an explicitly approved provider only.

## Discord acceptance test

- First completed real WARCON match triggers one and only one new recap after the match ends, with the actually generated 1080px PNG. Upload it as `match-recap.png`.
- The **Open in 1ADAAR** link button opens the exact matching match section on GitHub Pages on desktop and mobile Discord clients. The client, not Pillow, controls gallery rendered width.
- Top recorded-kills players for each faction appear only when match player lines are explicitly verified complete; else neutral unavailable. Ties correctly say multiple players tied.
- Next map + lighting + public join code goes in a **separate** verified, deduplicated announcement only when public WARCON status confirms the newly observed round and conditions.
- No usernames or text can ping @everyone or @here; screenshot and inspect actual messages (not HTML approximation).
- Verify no Discord webhook credentials, raw SteamIDs, economy balances or admin secrets appear in public GitHub Pages JSON, action artifacts, or message text.

**C.** Approve the frequency/content policy: recap once per completed match, next-map post only on confirmed data, weekly report Sunday at noon Eastern, no automatic user mentions.

**E.** Future slash commands/bot: **not necessary for the current one-way recap**. Approve new app scope and an HTTPS interaction backend later; no server-management workflow rewrite needed for present message delivery.

# v1.1.0 completion — progression and recap owner handoff

**PR:** #35 (draft, built from production main). **Production:** unchanged by this PR.

## Why the released version looked incomplete

The IA design branch contained a radar and Tracker research, but the live PlayerOne demo route never used the radar renderer. The real player route only showed six empty axes and a disabled 1ADAAR verification action. The site menu also differed across the home, player, map/team, activity and weekly pages. The Python recap renderer was updated and passed QA, but the owner had not received a full Discord-message visual review package.

## Delivered for owner review in PR #35

- The existing public fictional `docs/playerone-demo.html` now has the six-role chart before the performance graph. It uses `docs/js/role-radar.js`, a new strictly demo-only `docs/js/demo-progression.js`, an accessible six-role level/XP table, WARDOG level, career XP, and optional *fictional* cash/gold.
- User-facing buttons simulate **not connected → linked sample → refresh sample → disconnect sample**. The demonstration cannot authenticate, query Tracker or WARCON, or store IDs/consent. State resets on page reload.
- The example uses a **0–50 illustrative plotting axis only**. This is not a verified game role-level maximum, so real synced data remains gated until a reliable season cap or an explicitly labeled, mathematically valid non-cap axis is approved.
- The real `docs/players.html` page has individual empty rows for all six role levels/XP. It never shows synthetic numbers in a real dossier. The disabled Steam verification control stays disabled until a separately approved OpenID and consent service exists.
- Navigation now exposes map/team performance and Activity consistently across Home, Player, PlayerOne, Seasons, Comparison, Weekly and Map/Faction.
- Real message artwork remains `src/recap_card.py`; the container, attached artwork, neutral incomplete-player-line text and URL button contract remain `src/discord_contract.py`. This PR does not post Discord messages or modify the approved webhook.

## Review package

The owner was supplied the actual fictional production-renderer recap image plus desktop/mobile illustrative Discord message wrappers. Those mockups **are not screenshots from Discord itself**. The URL button in the illustration is disabled because no real match ID exists. Live messages use the verified match-ID URL and Discord Components V2.

## Release gates

1. Unit, privacy and browser checks pass at six screen widths with connected and unconnected PlayerOne sample states.
2. Compare actual screenshots to the existing IA reference for typography, panel spacing, chart scale and mobile readability.
3. Review the real recap PNG and simulated Discord-client layout; obtain explicit permission and a test destination to validate actual desktop/mobile Discord rendering.
4. Owner approves merging into production. Continue to protect live WARCON data and avoid a second hosting repository.
5. Before v1.1.1, remove all public fictional pages/assets and retain only internal CI fixtures; no fake records enter the real match collector.

## Why genuine progression is not connected yet

Tracker documents GET `/api/v1/players/{steamId}` for synced opted-in accounts, returning six role levels/XP, overall WARDOG level, career XP and optional cash/gold. It is read-only and does not expose an OAuth callback for 1ADAAR. A durable connected account and cross-device refresh requires independently verified Steam account ownership, consent persistence, private backend identity mapping and revocation. A public Pages bundle must not publish raw SteamIDs or private account balances. None of that authenticated service is provisioned by PR #35.

# 1ADAAR v1.1.0 — ONE unified IA/UX/UI facelift contract

**Status 2026-10-21: DESIGN/IMPLEMENTATION ALIGNMENT, NOT FULL RELEASE ACCEPTANCE.**
The owner identified a split: concept design screens were not turned into working code, while piecemeal implementation changes diverged from the intended facelift. This file explicitly makes one shared review contract for both disciplines. Do not treat a passed test as owner's visual approval, or a prototype as an implemented page.

## Direction — tactical after-action intelligence

The product should feel like one WARDOGS community operations center, not a collection of independent dashboards. The purpose is to make legitimate WARCON information immediately intelligible. No unsupported game telemetry, fictional live badges, copied brand marks, or unverified results.

- Official original 1AD emblem anchors community identity; authentic WARDOGS game artwork and approved faction emblems are unchanged. Never approximate them.
- Base everyday screens: deep charcoal #0d1411 / #151d19; high-contrast off-white #f5f8f5; restrained data-accent green #86f4a4. Kills are green; deaths yellow #f5c84b. Use each faction's verified official color only for faction identity and corresponding scores.
- Weekly recap/awards only: warm muted amber/gold #e4bd78, with actual silver and bronze in second and third. Gold is never an everyday performance accent.
- Clear editorial scale: game artwork as large header, small source/eyebrow, one meaningful strong title per page, readable 13–16px running text (on desktop), 4/8/12/16/24/32px spacing rhythm, unambiguous source labels.
- One-time hero perimeter laser, then original SVG-alpha-masked metallic glint; no infinite loops or rectangular overlay across the mark. Reduced motion and truthful blank/error states are required.
- No decorative rank badges competing with the first-place crown. All three numbers use identical rank typography and centered placement; crown (only if a genuinely eligible winner) sits below rank 1 and above that player's real, consented photo.

## Approved screen hierarchy, with clear answers

1. **Home / server briefing**: server identity, safely freshness-labelled status, useful navigation action, four high-signal known match summary figures, latest saved completed matches; no fabricated activity graph.
2. **Find a player / player dossier**: public WARCON all-time career headline (K/D, kills, deaths, matches), subordinate actual wins, playtime and seeding only if verified; single source-labelled career win-rate donut; map and faction appearance bars, actual observed match chart, recent saved report links. Keep saved match samples separate from all-time snapshots.
3. **Performance**: kills/deaths, per-match K/D, five-record rolling combined K/D, career WARCON snapshot K/D with source and window definitions immediately adjacent. Sample ranges do NOT change rolling denominator.
4. **Maps / factions / season history**: preserved completed-match subset with precise counts, denominators and provenance; real official faction graphics only.
5. **Recorded match activity**: global archived completed-match start grid, in Eastern time, and blank until actual matches exist. Not player-session surveillance.
6. **Weekly intelligence**: deliberately amber. No pretend community winner; first/second/third share one component style, verified first-place crown only when actually awarded; past weeks grouped by genuine seasons.
7. **Discord match recap**: the **same design vocabulary**, not a generic Discord embed. Source-rendered PNG with dramatic original battlefield/1AD/WARDOGS header, map, explicit winner if WARCON confirms, faction score bars and verified match highlights. Native Components V2 media gallery, one honest sentence and a live-report link. Separate next-map update only after actual changed map/conditions confirmed from WARCON.

## Review protocol — one direction only

- IA/UX/UI recommendations become acceptance requirements only after a named visual reference and owner approval; drafts alone are not source changes.
- Engineering changes must identify the exact design reference, actual changed files and screenshot evidence. Do not claim the independent engineer re-reviewed implementation without proof.
- Any newly staged screen must ship a clickable page or true screenshot (not a textual description), across phone and desktop, with a documented feature-parity check.
- Product copy must disclose fictional fixtures, unavailable results, absent Discord verification, and incomplete WARCON capture.
- Stage on `staging/v2.0-foundation`; keep PR #22 draft and `main` unchanged. Never send test webhooks without express authorization.
- Actual release needs full end-to-end live-source safety gates, a native Discord render check, and explicit owner approval.

# Real WARDOGS progression — Steam-verified 1ADAAR connection

**Status:** implemented as code, **not deployed**, not verified against a live Steam account. The existing GitHub Pages site stays unchanged until approved merge. Branch: `feature/v1.1.0-steam-verified-progression`.

## What this actually connects

WARDOGS Tracker [developer documentation](https://wardogstracker.gg/developers) provides a free read-only public API for players who **independently signed into Tracker with Steam and synchronized their WARDOGS game-account progression**. This is separate from Dan's community-server WARCON kills/deaths/matches and does not turn Tracker into Dan's RCON source.

- Real account totals: WARDOG level, career XP, six roles (Assault/Medic/Support/Recon/Driver/Pilot) level + XP, Tracker sync date
- Optional: cash/gold, only when both Tracker exposes it and user separately consents in 1ADAAR
- Not included: global match kills, universal WARDOGS K/D, weapon kill histories, Dan's game-admin permissions or game session data. Tracker's own documentation says global match K/D is not currently available.
- **Season caveat:** WARDOGS wipes role levels, XP, cash and unlocks on new seasons, while gold carries across seasons. Do not compare different seasons as one continuous level trend without season labels.
- The chart uses a **0–100 role level visual axis** based on the currently documented Tracker max level (the Tracker stats page identifies 100 as maxed), not WARCON's combat rankings.

## Why GitHub Pages cannot do ownership verification alone

Steam OpenID 2.0 returns signed authentication assertions that must be verified **server-side** with Steam. A static Pages-only JavaScript implementation could not protect authentication sessions, prove ownership, support revocation, or keep the signed-ID mapping private.

This package adds a small **Cloudflare Worker + private D1** service in `services/steam-progression/`. The site's JavaScript continues to load normally even when the Worker has not been activated. **No Steam API key is needed for OpenID 2.0**; this implementation uses Steam's official OpenID endpoint, not Steam credentials or passwords. The free Worker/D1 tiers are sufficient for initial authorized testing *subject to provider eligibility/quotas*. We do not enable paid billing.

## Owner/provider setup — necessary for live testing

1. Log into an owner-controlled [Cloudflare](https://dash.cloudflare.com/) account on its **Workers Free** plan. Do not provide login passwords, Steam passwords or keys to anyone or commit them. Creating this external account requires your explicit action.
2. In the repository's branch directory `services/steam-progression/`, create D1: `npx wrangler d1 create 1adaar-steam-consent`. Set the printed D1 database UUID in `wrangler.toml`. This database remains private and does **not** belong in public GitHub Pages.
3. Apply the schema (remote): `npx wrangler d1 execute 1adaar-steam-consent --remote --file=./schema.ddl`.
4. Deploy the Worker with `npx wrangler deploy`. Obtain its exact `https://<your-worker>.<your-subdomain>.workers.dev` endpoint.
5. Set `AUTH_ORIGIN` in `wrangler.toml` to this **exact Worker origin**, then redeploy. `PUBLIC_ORIGIN` remains `https://ejronin.github.io` and `PUBLIC_PAGE_URL` remains `https://ejronin.github.io/1ADAAR/players.html`. Only registered HTTPS hosts are accepted; this code cannot run as an open redirect.
6. Owner/test engineer sets the **public endpoint only** in `docs/js/progression-config.js` and ships it through approved Pages release. No SteamID, token or secret may be placed into this JS file. Until then, the Connect button remains disabled.
7. Test with your own account. On WARDOGS Tracker, sign in with Steam and sync your profile, allow the relevant public fields under its privacy settings. Then in 1ADAAR, find your real WARCON dossier, select **Connect with Steam**, sign in on Steam's real URL, return to the dossier, approve 1ADAAR public-progression consent and optional cash/gold consent. The graph and role table will fetch from Tracker through the Worker.
8. Test wrong-player linking (must fail), private/unknown Tracker profile (honest empty state), 429/rate limit, profile re-entry, two browsers, economy hidden, and Disconnect. A new device needs a fresh Steam sign-in; the consent record is retained server-side until revoked.

**Limitation for players not in WARCON's published top-1,000 dossier list:** the existing server dossier cannot be selected, so an authenticated standalone "My WARDOGS progression" page would be needed to serve those users. This scope specifically connects to a real, published WARCON dossier and rejects mismatches.

## Actual technical flow

```text
Public 1ADAAR WARCON dossier (64-char opaque player key)
  → Connect with Steam (client PKCE, no SteamID submitted)
  → Cloudflare Worker /auth/start (random, stored, five-minute one-time state)
  → steamcommunity.com/openid/login (user authenticates ONLY with Steam)
  → Worker /auth/callback (validate signed fields + server-side check_authentication)
  → Worker checks SHA256("1ADAAR:v1:" + verified SteamID) = chosen WARCON key
  → short-lived 90-second authorization code sent to original Pages profile
  → browser redeems code with original PKCE verifier (single use)
  → private, short-lived session; explicit progression/economy consent
  → Worker GET /api/v1/players/{steamId} on WARDOGS Tracker
  → return source-qualified, nonidentifying level/XP/economy values
  → show six-axis role radar, exact table, sync timestamp, Refresh, Disconnect
```

- All tokens and codes are random and single-use/short-lived; the browser session remains in same-tab sessionStorage and expires in 45 minutes. Refreshing that tab can restore it. Cross-device Steam re-verification is required (consent persists privately).
- The Worker uses CORS with an exact allowed GitHub Pages origin, a one-account/one-dossier key match, PKCE code exchange, explicit user opt-in and private D1 hashed session tokens.
- No SteamID or raw third-party profile URL is ever sent to the Pages client, logs created by our code, GitHub commits, Actions artifacts, or publicly deployed JSON. Raw SteamIDs are kept only in private D1 and Worker-to-Tracker requests.
- Six-source normalization never fills missing values. Tracker 404/private/unsynced means unavailable. A legitimate cash/gold value of 0 is displayed as zero; null/hidden stays hidden.
- Cached result lasts only 60 seconds in private D1. Disconnect deletes sessions/consent/cache. D1 is not an encrypted end-to-end user vault; Cloudflare operators' permitted infrastructure access and its privacy disclosures still apply.
- No cross-site third-party cookie is needed: short-lived single-use code + PKCE bridges the GitHub Pages/Worker origins. That avoids browser restrictions on third-party session cookies.

## Tests & QA

- `node --test tests/progression_auth.test.mjs`: Steam OpenID claimed identity, signed fields, exact callback origin, SHA key mapping, economy privacy, schema and invalid data.
- `python -m unittest discover -s tests -v`: existing WARCON privacy/normalization/publication tests.
- Browser QA at 320, 375, 390, 768, 1024 and 1440 must continue to show honest disabled-without-provider behavior and never expose private SteamIDs.
- Live authentication **cannot be validated** without Cloudflare Worker/D1 deployment and voluntary sign-in on Steam. No provider has been connected in this branch, and no real user has been authenticated or tracked yet.
- Rollback: remove endpoint from `docs/js/progression-config.js`; original Pages WARCON service and PlayerOne fictional examples continue to work.

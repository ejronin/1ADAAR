### Library risk / bundle

New npm dependencies: **zero**. Third-party libraries remain existing pinned Pillow, CairoSVG and CI-only Playwright. A later SCSS pipeline requires a lockfile, license audit, dependency security review, a build-artifact owner, and a Pages preview that does not overwrite production. D3 (BSD-3-Clause), Sass (MIT), Vite (MIT) are **not adopted** by this PR. Built-in JavaScript/SVG is sufficient and lighter for current charts. Keep unchanged original WARDOGS/1AD/faction trademarks and approved assets.

## v1.1.0 Tracker progression privacy boundary

WARDOGS Tracker documents free GET `https://wardogstracker.gg/api/v1/players/{steamId}` for opted-in **synchronized public** profiles, with six role XP/levels, overall Wardog level, career XP and possibly account cash/gold. Source: https://wardogstracker.gg/developers and its OpenAPI specification. Its endpoint is read-only; the Tracker Steam sign-in is NOT an OAuth callback for 1ADAAR.

**Tier 1 shipped to draft PR #29:** 1ADAAR remains a fully working WARCON dossier without linking. Real dossier offers a verified external sync link and honest no-connection state. Private Python normalizer and browser role radar renderer are source-gated and testable; they cannot claim ownership or show unverified data. No SteamID in public URLs; no economy snapshot committed to public JSON; no fake "connected" state.

**Tier 2 needs separate authorization:** Cloudflare Workers + D1 + secure session cookie + server-side Steam OpenID 2.0 authentication + explicit per-dossier consent + granular economy opt-in + private ephemeral profile sync + revoke/delete + correct private player key mapping. Do not provision until owner approves provider, retention/deletion policy, authentication domain, consent copy and data exposure. Steam OpenID proof must come from Steam's server-validated claimed ID (https://partner.steamgames.com/doc/features/auth). D1 is a private serverless SQL persistence store, **not part of GitHub Pages**. Approx. free quotas as of 2026-10-22: Workers Free 100k requests/day; D1 5m row reads/day, 100k writes/day, 5GB storage. Actual bills and free limits may change; verify in provider account before deployment (https://www.cloudflare.com/plans/).

**Alternative:** Supabase free-tier auth/database/Edge Functions with a separate server-side Steam OpenID validation adapter; check OAuth compatibility (Steam OpenID isn't generic OAuth 2). More moving services if the owner does not already use Supabase. Authentication correctness, refresh/revocation and secure logs are more important than automatic render. Do not use anonymous client-supplied SteamID as ownership proof.

**No source-verified maximum level:** radar stays blank until role level common axis bound and game season semantics are verified. Exact levels/XP rows are fallback for an authorized complete record.

## Discord architecture: build future-compatible rails now, not all future features

Continue `WARCON public collector → sanitized immutable completed-match ID → recap image and V2 payload → Discord webhook POST → delivery ID checkpoint → optional confirmed next-map webhook`. Separate *content generators* from *transport* and *administration*:

- Current v1.1 now supports real native Components V2 Container (17), Text Display (10), Media Gallery (12), Action Row (1), and link button (2/style 5) to exact first-party `#match-ID` report. Upload PNG as `attachment://match-recap.png`; webhook must send `flags=32768` and `with_components=true`. No `custom_id` on URL buttons.
- Match top-kills per Lonestar/Valkyra/Manticore only if match-player roster is provably complete. Deduplicate player key, detect ties, omit/neutral when incomplete. Current public WARCON player lines may be truncated at 120; the source has not confirmed a completion indicator. The collector therefore does NOT mark unverified lines complete.
- Continue one-way notification webhooks without Discord bot installation or privileged guild role changes.
- For v1.5 **slash commands / user-triggered lookups / RSVP / buttons with `custom_id` / moderation controls**, Discord requires an **installed Application**, authorization by a holder of the necessary guild permissions, a public HTTPS interactions endpoint or Gateway bot, verification of Discord request signatures and timely interaction acknowledgement. Webhook-only posting CANNOT receive user interactions. Prefer a signed edge function if the owner authorizes Cloudflare; do not implement new bot or manage members/roles unilaterally.
- Stage future Discord interaction contracts separately, with no privileged permissions by default. v1.5 workflow extends current match ledger rather than replacing collectors/webhooks.

**Operator/Discord admin approval checklist (before integration):** Dan approves which existing channel gets recaps and which gets weekly Sunday noon ET; confirm channel-level **Manage Webhooks**, View Channel, Send Messages, Embed Links/Attach Files as actually required for chosen integration; ensure secret webhook URL is stored as Actions secret, never commit or paste publicly; request separate private test channel/opt-in dry run. Verify Dan's posting frequency, moderation rules, membership/role eligibility, and whether a future bot is permitted. Installing Discord app/slash commands can require **Manage Server** or Dan's approval; operator's Manage Webhooks ability alone does NOT grant application install or role-management authority. Do not request Administrator or full member intent when no use case exists. `allowed_mentions.parse=[]` prevents accidental pings. No real Discord client QA has been performed by this PR.

## Milestone direction

**v1.1.0 target:** five chart modes + map K/D + verified source labels + IA layout + source-backed weekly archives + native V2 recap and link button + OPTIONAL Tracker connection UI + gated radar (filled only after authorized connection). Do not block site usability on Tracker, private session activity or unavailable leader completeness. A **fully functional persistent role display** requires Tier 2 approval and testing; UI/adapter alone does NOT satisfy that deployment condition.

**v1.5.0 candidate after real matches:** enhanced scoreboard/faction leaders once complete match feed verified; real session activity with privacy/coverage; optional progression history; Discord slash command exploration and automated interaction replies; improved anti-duplication/audit health and verified server-specific season analytics. This is design/contract work now, runtime provider installation later.

**v2.0 future:** deeper authorized read-only RCON/WARCON integrations, richer player/match history, evidence-based special combat comparisons, workflow and admin moderation when explicitly approved. No speculative unlock/loadout module and no invented weapon kill/death attribution.

**Decision approved:** 2026-10-20. **Build program:** originally called "v2"; **public release version:** **1.1.0**, not 2.0.0. **Future consolidation milestone:** **1.5.0**. Current production v1.0.1 stays live until explicit approval to merge the complete 1.1.0 release.

## Design system is frozen unless the owner signs off a change

- Preserve the existing, original **1AD** emblem and official **WARDOGS** imagery; don't redraw trademarks or substitute generated branding. Preserve source-derived authentic Lonestar/Valkyra/Manticore emblems/colors.
- Everyday dashboard and all player/data pages: **black, charcoal, white, restrained green**. Weekly Roundup/awards only: **muted amber/gold**, **silver**, **bronze** for podium ranks 1–3.
- Plain English, no invented percentages, capability claims, skill scores, user account links, or ranking eligibility.
- Use the two user-provided design references as IA/layout inspiration; do not copy their brand or unsupported statistics.

## IA / UX / UI acceptance pass — must be completed before the 1.1.0 merge

### IA — can a person find the right results?
- One logical path: **Find a player → player profile → Map & Team detail → completed match source**.
- "Current season", "All-time WARCON" and "Saved matches" visibly distinct, never mixed in one stat card without an explicit source label.
- Avoid redundant nav entries or unclear "rank" vs "character level". Make the weekly archive visible from the main navigation.
- Shareable URLs deep-link to a real pseudonymous player and selected season; on a missing player, offer search, not a broken panel.

### UX — does it work with a keyboard, phone, and missing data?
- Assess at 320/375/390/768/1024/1440 CSS pixels, standard and zoomed text (200%); mobile menu and bottom stats work without horizontal body scrolling.
- Touch areas >=44 px, strong focus states, tab order, skip link, meaningful screen-reader labels; color never the only encoding.
- Reduce motion if requested. No chart hover required to discover percentages, exact counts or meaning.
- Loading/error/zero-data/unknown-stat/no-verified-Discord-members states plainly communicate the truth.
- Each donut has **visible remaining track + correctly scaled colored arc + centered numeric percentage + plain-English legend + count/denominator**, using SVG circles with real 0–100 progress. Three profile donuts: recorded win rate, chosen faction participation, chosen map participation. Each must reference available saved records; fallback "—" instead of 0% for unknown results.
- No jumpy layout, clipped avatars, overflow, tiny captions or hard-to-read contrast in the "At a glance" panel.

### UI — design-quality checklist
- Brand assets exactly match official provided files, with no generated approximations.
- Use a consistent type scale, panels/gutters and shadows. Desktop 2-column chart hierarchy resembles reference 1; focused map rows resemble reference 2.
- Radial chart display is deliberately **donut**, not an unfilled disc. Use a clear center cutout, 12–16 px tracks, enough size on phones, labels in text and no misleading color legend.
- Faction colors stay source-correct, but most other charts stay restrained green. Weekly only uses amber/gold/silver/bronze.
- Inspect actual browser screenshots on mobile and desktop; iterate after owner feedback. GitHub CI passing alone does not satisfy visual QA.

## Engineering/release validation gates

1. Feature checklists above implemented and reviewed on a staging branch. Tests run on the same proposed merge SHA and pass.
2. Run accessible browser checks, narrow phone screenshots, responsive interaction and keyboard review, plus metadata/cache/version and direct-link checks.
3. Test privacy of public artifacts: no raw Steam IDs, private Discord mappings, webhooks, OAuth tokens, join codes, or unauthorized user avatars.
4. Test data edge cases: no completed matches, incomplete feed, unknown result, 0 deaths, identical map rankings, cutoff across official season boundary, game updates and WARCON API unavailable.
5. Test Discord eligibility with a private fixture, revoked/no-longer-member cases, no double-post of weekly award; test opt-in admin alert destination & quiet-period behavior.
6. Verify GitHub Pages/status snapshot/rollback against v1.0.1; explicit owner UAT approval to replace production. **Never merge solely because CI is green.**
7. First genuine WARCON/Discord delivery validation remains required for statements that real live results work. If it cannot occur pre-release, display truthful empty states, record a clear post-launch check and require owner sign-off for that exception.

## 1.5.0 future revisit (NOT a catch-all for unfinished 1.1.0)

- More sophisticated combat heatmaps **only with verified positional feed**; advanced map/weapon metrics and player goals; stronger opt-in community integrations; data longevity or hosting migration only if justified.
- A postponed *required* 1.1.0 feature requires a conscious scope decision and explicit owner approval—nothing silently moves to 1.5.0.
